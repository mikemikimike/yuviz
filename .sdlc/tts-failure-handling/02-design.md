# Design: TTS failure handling in the conversation pipeline

## Approach
Fix "no audio" at its single source: `_synthesize_sentence_stream` (`pipeline.py:1942`) drops zero-length chunks and treats a stream that ends without a non-empty chunk exactly like one that raised (unspoken-sentence tracking, a WARNING). Every caller already keys its "got audio" flag off "a chunk was yielded" (`pipeline.py:1026`, `1119`, `1253`, `1260`, `1406`), so the zero-byte holes in #174 and #205 item 7 close without touching those branches. `_spoken_reply` joins sentences per boundary by script (#220). For #219 the max-duration branch records only what played and marks its EndCall as audio-less; the servicer sends that one EndCall with a distinct reason, and the gateway applies an EndCall carrying that reason at once, straight into `WaitingForHangup`, instead of parking it in `pending_end_call_` for a playback-finished that has nothing to finish. Keying the gateway on the reason scopes the C++ change to exactly the no-playback max-duration case, and because that path never sets `pending_end_call_` there is nothing for a later turn to consume (AC13) — no reliance on the empty final frame draining in a particular order.

## Data
None.

## Interfaces
- `HandlerResponse.end_call_without_audio: bool = False` (`session.py:55`). Only the pipeline's max-duration branch sets it.
- `_join_sentences(sentences: list[str]) -> str` (module-private, `pipeline.py`, next to `_spoken_reply`).
- `_synthesize_sentence_stream` signature is unchanged. Its contract changes: it never yields `b""`, and a stream with no non-empty chunk counts as a failure for `in_reply`.
- Wire: `EndCall.reason = "max_duration_no_audio"` is a new reason value on the existing proto field; no proto change. The gateway matches it as a string constant defined once in `CallSession.cpp`; the servicer uses the same literal.
- `void CallFSM::on_end_call_without_playback(std::chrono::milliseconds goodbye_timeout_override = {});` — zero means the FSM default, as for `on_playback_finished`.
- `bool CallSession::end_call_pending() const noexcept;`

## Risks
- Callers that relied on receiving `b""`: the grep of `_synthesize_sentence_stream` callers (14 sites, listed under Changes) shows each one either iterates and forwards chunks or, for the greeting at `:872`, collects them into a list. A greeting that yielded `[b""]` now yields `[]`, the same value a provider with zero chunks already produced, so the servicer greeting path already handles it.
- Deploy skew: a gateway without this change treats `max_duration_no_audio` like any reason and sets `pending_end_call_` with no playback to consume it, which is today's leak. Mitigation: the gateway ships in the same release and is rolled out before the conversation service; the PR states this order.
- `on_end_call_without_playback` in `Speaking` cuts any still-queued filler audio at the grace timeout. Acceptable: no goodbye exists to protect, and the grace period is the same one a played goodbye gets.
- The new `HandlerResponse` field could be set by a future caller to get around the audio gate. It has one setter, the docstring scopes it to the hard cap, and the AC17 test asserts that `[[END_CALL]]` with no audio still sends no EndCall.
- AC6 and AC7 demand tests that fail on base `redesign`, but `phrase_audio.py:46` and `:91` already refuse to cache or replay an empty result, so those tests are expected to pass on base. Mitigation (lesson 12): write them with genuinely overlapping callers (lesson 53) and run them on base; if they pass there, the PR names them as regression guards that were not exercised against a bug, instead of weakening the fixture to force a failure.
- No CallSession test fixture exists today. The new test builds one from `NullConversationTransport`-style test-local transport that keeps its callbacks, an inline `IDispatcher`, a counting `ITimerService`, and `EslClient(EslConfig, Logger&)` with no connect (as `esl_client_test.cpp` constructs it). If a constructor dependency cannot be built offline, the implementer reports AC13 blocked rather than downgrading it to an FSM-only test.
- Mixed-script replies, such as a Japanese sentence followed by an English one: the boundary rule looks only at the left sentence's terminator. `。` followed by English joins with no space, which matches how the model wrote it, since `_SENTENCE_RE` consumed no whitespace there.

## Test plan
Python tests are unit tests with fake TTS providers, using the existing fixtures in `tests/test_pipeline.py`, `tests/test_end_call_guard.py` and `tests/test_servicer.py` at the deployed constants (lesson 25). Gateway tests are GoogleTest in `gateway_tests`. Each must fail on base `redesign`, except as noted for AC6-7 under Risks (lesson 12).
1. Zero-byte reply sentence: one fake yields nothing and another yields only `b""` for "-5 degrees outside today." while "Second." succeeds. The stored transcript and history equal "Second.", no `b""` reaches `tts_payloads`, and the second sentence's audio is still yielded (AC1-4). One raising case confirms PR #200 behaviour is unchanged and the terminal chunk is still sent (AC5, 22).
2. Fixed-phrase cache: (a) two concurrent requests for one greeting, the first provider call returning empty audio and the second real audio, with the second request started while the first is in flight; the second request receives audio (AC6). (b) The same phrase requested twice in sequence, for a greeting and for a filler; the second call is synthesized again and yields audio (AC7).
3. `_spoken_reply` joins: `["我很好。","失败。","谢谢。"]` with the middle sentence failed gives `我很好。谢谢。`, Japanese gives the equivalent, English keeps single spaces, and "No." versus "Account No. 4512" is unchanged (AC8-10).
4. Max-duration with the goodbye and fallback both yielding `b""`, and separately both raising: `record_turn` stores the caller's text with agent text `""`, the last response has `end_call=True, end_call_without_audio=True`, and the WARNING is logged; fallback-plays gives `fallback_goodbye`; the goodbye-plays control is unchanged (AC11, 12, 14). Servicer AC17 test: one servicer runs a max-duration no-audio turn and an `[[END_CALL]]` no-audio turn; the first sends exactly one `EndCall(reason="max_duration_no_audio")` after the terminal chunk, the second sends none and the pipeline's "End of call withheld" WARNING is logged. A response with `tts_payloads=[b""]` leaves `audio_sent` false.
5. Gateway FSM (`call_fsm_test.cpp`): from `Thinking`, `Synthesizing` and `Speaking`, `on_end_call_without_playback(ms)` enters `WaitingForHangup` with the override, a following `on_playback_finished(false, false)` changes nothing, and the goodbye timeout closes the session, so the call ends on that turn (AC12, 15). From `BargeIn` it is a no-op. `EndCallPending_EntersWaitingForHangup` passes unmodified (AC14, 23).
6. Gateway CallSession (`call_session_end_call_test.cpp`), AC13 as restated by the PRD review: fire `on_tts_started`, `on_end_call(reason="max_duration_no_audio")` and an empty final `on_tts_chunk`, drain the outbound queue so `on_playback_finished` fires; assert `end_call_pending()` is false and `fsm_state()` is `WaitingForHangup`. Then fire another `on_playback_finished` on the same CallSession and assert zero additional hangups: the goodbye timer was armed exactly once and the state did not change. Control: `reason="agent_ended_call"` still leaves `end_call_pending()` true until playback finishes.
7. `[[END_CALL]]` with the reply, farewell and fallback all zero-byte, and separately all raising: no `end_call` response, `abandon_end()` is called, and the "End of call withheld" WARNING is logged. Farewell-plays and reply-plays controls still end the call. A barge-in variant sends no EndCall or transfer. Transfer announcement zero-byte and raising cases each log the WARNING and still yield `transfer_request` (AC16, 18-21).

Run: `pytest -q services/conversation/tests/test_pipeline.py services/conversation/tests/test_end_call_guard.py services/conversation/tests/test_workflow_pipeline.py services/conversation/tests/test_servicer.py services/conversation/tests/test_phrase_audio.py`, the gateway `gateway_tests` binary, then `pytest -q tests/` with the artifacts `git add -N`'d (lesson 55).
